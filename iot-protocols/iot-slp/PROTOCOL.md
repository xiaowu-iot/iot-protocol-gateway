# SLP 智能储物柜通信协议 V1

SLP（Smart Locker Protocol）是本项目虚构的私有协议，用来演示如何从零设计一个设备通信协议。场景：快递柜、寄存柜这类带多个格口的储物柜，通过 4G 连接平台，上报格口状态、接收开门指令、远程升级固件。

## 1. 通信方式

- 设备作为 TCP 客户端，主动连接平台，长连接
- 设备连上后先发**登录**，登录成功前平台不处理其他消息
- 心跳间隔由平台在登录应答里下发，平台在 3 倍心跳间隔内收不到任何数据，判定设备离线

## 2. 数据类型

| 类型 | 说明 |
|---|---|
| BYTE | 无符号 1 字节 |
| WORD | 无符号 2 字节，**大端** |
| DWORD | 无符号 4 字节，**大端** |
| QWORD | 无符号 8 字节，**大端** |
| STR | 1 字节长度 + ASCII 内容，长度不含自身 |
| TIME | DWORD，UTC 时间的 Unix 秒数 |

## 3. 帧结构

```
 0      2      3      4        6            14       16        16+N
 ┌──────┬──────┬──────┬────────┬────────────┬────────┬─────────┬──────────┐
 │ 帧头  │ 版本  │ 命令  │ 流水号  │   设备 ID   │  长度   │  数据    │  CRC16   │
 │ AA 55│ 01   │ BYTE │ WORD   │   QWORD    │  WORD  │  N 字节  │  WORD    │
 └──────┴──────┴──────┴────────┴────────────┴────────┴─────────┴──────────┘
```

| 字段 | 说明 |
|---|---|
| 帧头 | 固定 `AA 55` |
| 版本 | 协议版本，当前为 `01` |
| 命令 | 见第 4 节。**应答的命令 = 请求的命令 \| 0x80** |
| 流水号 | 发送方自增，0~65535 循环。**应答的流水号和请求相同** |
| 设备 ID | 出厂时写入，全局唯一 |
| 长度 | 数据部分的字节数，不含 CRC |
| 数据 | 由命令决定 |
| CRC16 | CRC-16/MODBUS，**范围从版本到数据末尾**（不含帧头），**高字节在前** |

没有转义，没有帧尾，最大帧长 8192 字节。

## 4. 命令

| 命令 | 应答 | 方向 | 说明 |
|---|---|---|---|
| 0x01 | 0x81 | 设备 → 平台 | 登录 |
| 0x02 | 0x82 | 设备 → 平台 | 心跳 |
| 0x03 | 0x83 | 设备 → 平台 | 格口状态上报 |
| 0x10 | 0x90 | 平台 → 设备 | 开门 |
| 0x20 | 0xA0 | 平台 → 设备 | 升级通知 |
| 0x21 | 0xA1 | 设备 → 平台 | 请求固件分片 |
| 0x22 | 0xA2 | 设备 → 平台 | 升级结果 |

### 4.1 登录 0x01

| 字段 | 类型 | 说明 |
|---|---|---|
| 固件版本 | STR | 比如 `1.0.0` |
| 格口数 | BYTE | |

**应答 0x81**

| 字段 | 类型 | 说明 |
|---|---|---|
| 结果 | BYTE | 0 成功，1 设备未登记，2 协议版本不支持 |
| 服务器时间 | TIME | 设备用来校准时钟 |
| 心跳间隔 | WORD | 秒 |

### 4.2 心跳 0x02

数据为空。应答 0x82 数据为空。

### 4.3 格口状态上报 0x03

格口状态变化时立即上报，另外每 10 分钟全量上报一次。

| 字段 | 类型 | 说明 |
|---|---|---|
| 时间 | TIME | 状态变化的时间 |
| 数量 | BYTE | 后面有几个格口 |
| 格口号 | BYTE | 从 1 开始，重复"数量"次 |
| 状态 | BYTE | bit0 门开，bit1 有物品，bit2 故障；重复"数量"次 |

**应答 0x83**：结果 BYTE，0 成功。设备 10 秒内收不到应答则重发，最多 3 次。

### 4.4 开门 0x10

| 字段 | 类型 | 说明 |
|---|---|---|
| 格口号 | BYTE | |
| 订单号 | STR | 平台的业务单号，设备原样记录在本地日志里，方便对账 |

**应答 0x90**

| 字段 | 类型 | 说明 |
|---|---|---|
| 结果 | BYTE | 0 成功，1 格口不存在，2 门锁故障，3 门已经是开的 |

### 4.5 升级通知 0x20

| 字段 | 类型 | 说明 |
|---|---|---|
| 版本 | STR | 目标版本 |
| 大小 | DWORD | 固件总字节数 |
| CRC32 | DWORD | 整个固件的 CRC32，设备下载完后校验 |

**应答 0xA0**：结果 BYTE，0 接受，1 已经是这个版本，2 设备忙（比如正在开门），稍后再试。

### 4.6 请求固件分片 0x21

设备接受升级后，**由设备主动按偏移请求分片**，一片收到再请求下一片。设备断线重连后，从本地记录的偏移继续请求，实现断点续传。

| 字段 | 类型 | 说明 |
|---|---|---|
| 版本 | STR | 要下载的版本 |
| 偏移 | DWORD | 从第几个字节开始 |
| 长度 | WORD | 请求多少字节，不超过 4096 |

**应答 0xA1**

| 字段 | 类型 | 说明 |
|---|---|---|
| 结果 | BYTE | 0 成功，1 版本不存在，2 偏移超出范围 |
| 偏移 | DWORD | 和请求一致 |
| 数据 | 剩余全部字节 | 最后一片可能比请求的短 |

### 4.7 升级结果 0x22

| 字段 | 类型 | 说明 |
|---|---|---|
| 版本 | STR | |
| 结果 | BYTE | 0 成功，1 CRC32 校验失败，2 写入失败 |

**应答 0xA2**：结果 BYTE，0 成功。

## 5. 版本兼容

- 新版本只能在数据**末尾追加**字段，接收方遇到多出来的字节直接忽略
- 改变已有字段的含义、长度，必须升级帧里的"版本"字段
- 平台同时支持多个版本，设备登录时如果版本不支持，返回结果 2

## 6. 示例

设备 202610170001 登录，固件版本 1.0.0，24 个格口，流水号 1：

```
AA 55 | 01 | 01 | 00 01 | 00 00 00 2F 2C 81 D8 91 | 00 07 | 05 31 2E 30 2E 30 18 | C0 8E
帧头   版本 命令 流水号  设备 ID                   长度    数据                   CRC16
```

数据：`05` 是版本字符串长度，`31 2E 30 2E 30` 是 "1.0.0"，`18` 是 24 个格口。CRC 从版本 `01` 算到数据末尾 `18`。
