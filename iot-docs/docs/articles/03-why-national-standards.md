# Java 程序员的 IoT 协议入门（三）：国内的 IoT 为什么绕不开国标协议

上一篇说到，国内很多设备用的是"TCP + 国标协议"。这一篇来聊两个问题：

1. 为什么会有这么多国家标准和行业标准？
2. 哪些行业在用哪些协议，作为 Java 程序员该从哪里学起？

## 为什么要有标准协议

先想象一下没有标准的世界。

某省要监管全省的危险品运输车辆，车上装的定位终端来自几十家厂商，每家的协议都不一样。监管平台要对接几十套协议，换一家供应商就得重新开发一遍。

**标准协议解决的就是这个问题：只要设备和平台都遵循同一个标准，任意厂家的设备都能接入任意厂家的平台。**

更关键的是，很多行业的标准是**政策强制**的。比如营运车辆必须安装符合标准的终端，并接入监管平台；重点排污单位的在线监测设备必须按标准上传数据。这就意味着：

- 这些行业的设备，一定用的是标准协议
- 做这些行业的项目，一定要懂这些协议
- 需求是长期、稳定存在的，不会因为技术潮流变化而消失

这就是为什么"懂协议"这项能力，在国内 IoT 行业里一直很值钱。

## 标准编号怎么看

先认识一下这些编号，以后看文档就不会一头雾水：

| 前缀 | 含义 | 例子 |
|---|---|---|
| GB | 强制性国家标准 | GB 26875 |
| GB/T | 推荐性国家标准（T 是"推荐"的拼音首字母） | GB/T 28181、GB/T 32960 |
| JT/T | 交通运输行业推荐性标准 | JT/T 808、JT/T 1078 |
| HJ | 生态环境行业标准 | HJ 212 |
| DL/T | 电力行业推荐性标准 | DL/T 645 |

后面的年份代表版本，比如 JT/T 808-2019 就是 2019 年修订的版本。**同一个协议的不同版本可能不兼容**，对接时第一件事就是确认设备用的是哪个版本。

## 各行业常见的协议

### 车联网：JT/T 808 系列（最值得学）

这是国内设备数量最多、应用最广的协议族之一。

| 协议 | 用途 |
|---|---|
| **JT/T 808** | 车载终端与平台之间的通信：注册、鉴权、位置上报、报警、参数设置、指令下发 |
| **JT/T 1078** | 车载视频：实时视频、录像回放、对讲 |
| JT/T 809 | 平台与平台之间的数据交换，比如企业平台向政府监管平台转发数据 |
| 主动安全扩展（俗称"苏标""粤标"等） | 驾驶员疲劳检测、前车碰撞预警等报警，以及报警照片、视频附件的上传 |

适用场景：两客一危（客运、旅游包车、危险品运输）车辆、重型货车、渣土车、网约车、公交、驾校、物流……只要是营运车辆，基本都绕不开它。

**为什么推荐从 808 学起？**

- 用的行业多，项目多
- 协议设计很典型：帧标识、转义、消息头、流水号、分包、应答机制全都有，学会了 808，再看其他二进制协议会非常轻松
- 资料相对多，有问题能找到人交流

### 新能源汽车：GB/T 32960

电动汽车需要把电池电压、温度、故障等数据实时上报给监管平台。车企、电池厂、换电运营商的平台都要对接它。

### 环保监测：HJ 212

污染源在线监测设备（废水、废气、空气质量站）向环保平台上传数据。

它和 808 最大的区别是**文本协议**，报文长这样：

```
##0101QN=20160801085857223;ST=32;CN=1062;PW=100000;MN=010000A8900016F000169DC0;Flag=5;CP=&&RtdInterval=30&&1C80
```

肉眼就能看懂一部分。但它也有自己的坑，比如 CRC 校验算法和常见的 MODBUS CRC 不一样，很多人第一次对接时校验怎么也对不上。

### 视频监控：GB/T 28181

摄像头、录像机接入视频平台的标准，基于 SIP 协议，和上面几个的路数完全不同，开源社区已经有比较成熟的实现。

### 其他行业

| 行业 | 常见协议 |
|---|---|
| 电力 | DL/T 645（电能表）、IEC 104 |
| 工业现场 | Modbus RTU / TCP（不是国标，但已经是事实上的标准） |
| 消防 | GB 26875（城市消防远程监控系统） |
| 充电桩 | 各运营商的私有协议，也有行业通用的协议 |

### 还有大量的厂家私有协议

除了标准协议，实际项目中遇到最多的，其实是**厂家私有协议**：智能门锁、储物柜、环境传感器……每家都有自己的一套。

好消息是，绝大部分私有协议都在模仿标准协议的设计：帧头、长度、命令字、数据、校验、帧尾。**学会读一份标准协议，就学会了读所有协议。**

我接得最多的私有协议在环卫项目里：垃圾桶的满溢监测、上桶计数，还有公厕里的各种传感器，几乎每个厂家一套协议。见过的"奇葩"设计大概有这几类：

- **长度字段的范围说不清**：文档写"长度"，到底包不包括帧头、包不包括自己、包不包括校验，只能拿真实报文去凑
- **校验只写"CRC16"**：不说是哪一种 CRC16，也不说高字节在前还是低字节在前
- **大小端混用**：同一条报文里，有的字段大端，有的字段小端，大概是不同的人写的固件
- **文档和设备对不上**：固件升级了，协议多了几个字段，文档还是旧的，报文里也没有版本号

所以拿到私有协议的第一件事，不是写代码，而是**向厂家要几条真实报文**，对着文档一个字段一个字段地核对。

## 作为 Java 程序员，该怎么学

我的建议是：

1. **先打基础**：二进制、位运算、大小端、校验算法。这是所有协议的共同基础，下一篇就讲
2. **再学一个典型协议**：从 JT/T 808 开始，它的设计最完整，学透一个就能举一反三
3. **然后学一个风格不同的**：HJ212 是文本协议，可以和 808 形成对比
4. **最后按需扩展**：项目用到什么就学什么，有了前面的基础，新协议一般几天就能上手

另外一个很重要的能力，是**读协议文档**。协议文档的写法其实很有规律：帧结构、字段表、数据类型定义、交互流程。掌握了规律，拿到任何一份新文档都知道该从哪里看起。这部分后面也会专门讲。

## 小结

- 国内很多行业有政策强制的标准协议，所以相关的需求长期稳定存在
- 车联网的 JT/T 808 系列应用最广、设计最典型，最适合作为第一个学习的协议
- 私有协议大多模仿标准协议的设计，学会一个，就能举一反三
